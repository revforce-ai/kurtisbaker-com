# Salesforce → air.ngo Drive backup

Archive the Attitudes In Reverse® Salesforce **Organization Data Export** into
Google Drive and keep the archive pruned to the retention policy.

## What this backs up

Salesforce emails a "Your Organization Data Export has completed" notice to
`kurt@air.ngo` every Wednesday. The export is one or more `.zip` files
(`WE_00D...0001.ZIP`, `...0002.ZIP`, …) generated by **Setup → Data Export** for
org **`d61000000zqczeaw`** ("Attitudes In Reverse®"). The download link is only
valid for **48 hours**, so this should be run within a day or two of the email.

- **Sender:** `noreply@salesforce.com`
- **Subject:** `Your Organization Data Export has completed - Attitudes In Reverse®`
- **Export page:** `https://d61000000zqczeaw.my.salesforce.com/ui/setup/export/DataExportPage/d`

## Destination

Google Drive account: **air.ngo**

```
My Drive / Backups / Salesforce - Attitudes In Reverse / <YYYY> / AIR-Salesforce-Backup-<YYYY-MM-DD>.zip
```

- Use the **export date** (the email's `Date:`, in `YYYY-MM-DD`) in the filename,
  not the day you happen to run it.
- If the export is split across multiple zips, suffix them:
  `AIR-Salesforce-Backup-<YYYY-MM-DD>-01.zip`, `-02.zip`, …
- Create the `Backups / Salesforce - Attitudes In Reverse / <YYYY>` folders if
  they don't exist yet (first run).

## Procedure

### 1. Find the export email
Search the **air.ngo** mailbox and read the most recent matching message:

- `gmail_search` (account `air.ngo`): `from:noreply@salesforce.com subject:"Data Export has completed"`
- `gmail_read` the newest hit and confirm the `Date:` is within the last 48h.
  If the newest email is older than 48h, the link has expired — tell the user a
  fresh export must be generated in Salesforce first, and stop.

### 2. Download the export from Salesforce
The export page and the per-file download URLs
(`/servlet/servlet.OrgExport?...`) require an **authenticated Salesforce
session** — they cannot be fetched anonymously, and no Salesforce credential is
wired into this environment by default.

Get the bytes using whichever path is available, in order of preference:

1. **Salesforce MCP / API** — if a Salesforce tool or a valid session id /
   OAuth token for org `d61000000zqczeaw` is available this run, list the export
   files on the Data Export page and download each `.zip`.
2. **Provided session** — if the user pastes a valid `sid` session cookie (or an
   `Authorization: Bearer` token), fetch each `servlet.OrgExport` file with it.
3. **Human hand-off** — otherwise ask the user to download the zip(s) from the
   export link and attach them, then continue from step 3.

Do not invent a download path or claim success without the actual bytes.

### 3. Upload to Drive
Put each zip in the destination folder (see **Destination**) using the air.ngo
Drive, preserving the dated filename. Verify the uploaded file size matches the
source before treating the copy as complete. Upload to a temporary name and
rename on success so a failed/partial upload never looks like a good backup.

### 4. Prune to the retention policy
Run the retention pass over the destination folder — see below.

### 5. Report
Tell the user what was archived (filename, size, Drive link) and list any files
the prune step deleted.

## Retention policy

> Keep **weekly for the last 30 days** and **monthly for the past year**.

Concretely, relative to today:

| Age of backup        | Keep?                                          |
|----------------------|------------------------------------------------|
| ≤ 30 days            | Keep **all** weekly exports                    |
| 31 days – 12 months  | Keep the **newest export per calendar month**  |
| > 12 months          | Delete                                          |

The most recent backup is always kept. Deletions are permanent, so confirm the
delete list with the user (or run `--dry-run` first) unless they've said to run
unattended.

### Running the prune

`scripts/prune_backups.py` decides what to keep vs. delete — it has no Drive
dependencies, so it's safe to run anywhere. Feed it the folder listing as JSON
(`[{"name": "...", "id": "<driveFileId>", "date": "YYYY-MM-DD"}, ...]`) where
`date` is the backup's export date (parse it from the filename if needed):

```bash
python3 scripts/prune_backups.py backups.json            # show keep/delete plan
python3 scripts/prune_backups.py backups.json --delete   # print only IDs to delete
python3 scripts/prune_backups.py backups.json --today 2026-06-17   # pin "now" for testing
```

To prune: get the listing with `drive_search` (account `air.ngo`,
`query: "'<folderId>' in parents and trashed = false"`), pass it through the
script, then delete each returned file id from Drive. Trash (recoverable) rather
than hard-delete when the Drive tool offers the choice.

## Notes
- This is meant to run weekly. A natural cadence is a `/loop` or a scheduled
  session every Wednesday afternoon, after the export email lands.
- If multiple export emails are unprocessed (e.g. a few weeks were missed),
  back up each one under its own export-date filename, then prune once at the end.
